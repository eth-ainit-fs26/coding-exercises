Welcome to the Ge'ez Game! You'll learn how Large Language Models (LLMs) work - by playing. We use Ge'ez, an ancient Ethiopian language, so you and the model start on equal footing: zero intuition, pure pattern recognition.

Every sentence in our mini-universe follows this structure:

Subject
→
lay + Direction
→
Object

For example:

bet  lay qeddām  mäskot
faras  lay ʾaḥar  gädam
sähän  lay ʾasmāl  mäṭräb

Each sentence lives in one of two worlds - City or Countryside. Your job: read the sentence and guess which world it belongs to. You don't need to understand every word - just learn to spot which nouns belong to which world. That's exactly how an LLM classifies text: by recognizing token patterns.

The direction words (qeddām = in front of, ʾaḥar = behind, ʾasmāl = left, ʾaymān = right) and the connector lay ("is") appear in both worlds - they don't help you classify. Focus on the nouns. For instance, the same direction word can appear in a City sentence and a Countryside sentence:

City:  mäkina  lay qeddām  bet
Countryside:  faras  lay qeddām  gädam

lay qeddām is identical in both — only the nouns reveal the world.

Two valid sentence patterns exist:

Subject lay Object
Subject lay qeddām / ʾaḥar Object

The two direction words: qeddām = in front of, ʾaḥar = behind. They are optional — a sentence is valid with or without them.

Why can't I say some things? The sentences in this game describe a fixed mini-universe: each noun has a specific location, and only some spatial relationships hold. Just like in the real world you can't say "Paris is behind London" without it being false, here sentences that contradict the universe's layout are simply not valid.
Specific examples: gāzā lay ʾaḥar ʿEmäk is not valid because in our universe valley (ʿEmäk) and mountain (gāzā) don't stand in that relation. Similarly, ʿIqlēsīya lay … ʿIqlēsīya is never valid — an object can't be placed relative to itself. This is exactly how LLMs learn constraints: from patterns in data, not from explicit rules.

Challenge 3: The Prediction Table instructions

▼

At its core, a language model (LM) is a next-token predictor. Given a prefix (the tokens seen so far), it outputs a probability for every possible next token. These probabilities form a conditional probability table - and you'll build one by hand.

Here are the 5 sentences in our mini-corpus:

#Ge'ez
1gāzā lay daqqān
2gāzā lay ʾaḥar maytān
3gāzā lay qeddām ṣadäq
4ʿIqlēsīya lay ʾaḥar maytān
5ʿIqlēsīya lay qeddām may

How to fill each cell: count how often a token follows a given prefix, then divide by the total number of continuations for that prefix.

P( next token | prefix ) = times this token follows the prefixtotal continuations for this prefix

The table uses two special tokens you'll see as row labels: START marks the beginning of a sentence — it's the "empty prefix" before any word has been generated. END marks the point where the model decides the sentence is complete. Real language models use exactly the same trick (often written <BOS> and <EOS>).

Example - row "START": Out of 5 sentences, 3 start with gāzā and 2 with ʿIqlēsīya. So P(gāzā | START) = 3/5 = 0.6, P(ʿIqlēsīya | START) = 2/5 = 0.4. All other cells in that row stay empty.
Example - row "gāzā lay": After this prefix, the next token is ʾaḥar (1×), qeddām (1×), or daqqān (1×) - each 1/3 ≈ 0.33.

The table is pre-filled with zeros. Your job: figure out which zeros need to change, and to what value. Enter values as decimals (0.33), fractions (1/3), or percentages (33%). Click Check next to any row header to validate that row.
